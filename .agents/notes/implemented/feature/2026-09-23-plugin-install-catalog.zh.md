# Agent Note: 安装对话框里的部署自有插件目录

Status: implemented

[English](2026-09-23-plugin-install-catalog.md) | 中文

## Problem

插件页的**添加插件**对话框只接受一个安装 spec：包名、Git 地址、压缩包或绝对路径。不知道插件包名的人因此无法添加插件，页面也没有任何地方能看到某个部署提供了什么。改用查询注册表来发现同样不可行：npm 的搜索按名称、关键词和热度作答，而已发布的包 manifest 里没有任何字段标明它是 Nero 组合包。

## Decision

`plugin-manager` 新增 `catalog` 配置字段：一个有序的 `{ spec, title, description }` 列表，默认给出已发布的实验性 auto-review 包。`pluginManager.catalog()` 答复这些条目，并补上本 profile 的组合包与依赖、或安装自身的依赖是否已经持有每个 spec 所指的包。spec 的包名不安装即可读出：注册表包名即 spec 写的形式，本地目录读它自己的 manifest 名字。git 地址与压缩包要等 pnpm 拉取后才知道包名，因此这类条目永远不会被报为已安装。

Web 对话框打开时读取该目录，并把它列在输入框下方，每一项自带**安装**按钮，填入输入框后走与手输 spec 相同的检查与安装路径。本 profile 或安装已经持有的条目显示为**已安装**且没有控件：Host 明说这一点而不是把条目藏起来，人因此能看到自己找的插件本来就在。部署配置成空列表时不显示该列表。

目录承载的是部署数据，不是产品文案。条目文字在任何客户端语言下都按原样显示，部署在自己的 profile patch 里替换这份列表，增加一个插件无需改动客户端。

## Alternatives considered

**在对话框里查询注册表搜索。** npm 的公开搜索没有针对这些包的标记，且没有任何 `@nero/*` 包已发布，关键词搜索会返回其他生态里无关的包。每个结果还要先过现有的 spec 检查才能安装，于是对话框拿到的是一份只能偶尔装上的列表。

**把列表作为客户端包里的常量。** 这样一来提供什么由 UI bundle 决定，改动列表就要 fork 并重新构建客户端，客户端也无法判断 profile 已经持有哪些条目。

**从安装自身的包推导列表。** 只有启动器在 `OPTIONAL_BUNDLES`（[随安装提供的可选组合包](../process/2026-09-15-shipped-optional-bundles.zh.md)）里点名的组合包是随安装提供且默认关闭，而官方分组已经把它们连同开关列出来了；其余组合包要么内置于某个 profile，要么根本不在，推导出的列表只会重述那个分组。

**改为扩充 `OPTIONAL_BUNDLES`。** 该机制提供的是安装已经随附的组合包，第三方插件并不是；它也无法承载用来介绍条目的文字。

## Consequences

由部署、或用户自己的 profile patch 决定对话框提供什么。随附默认项指向的包在源码检出里并未发布到 npm，在那种环境下安装它会得到现有的 `not-found` 一句话；把条目改指私有源、git 地址或绝对路径是部署自己的编辑选择。

每次打开对话框花费一次 `catalog()` 读取，加上每个指向本地目录的条目一次 manifest 读取。这份列表本身不附带任何安全承诺：条目与手输 spec 一样要过同一套检查、注册表选择和 pnpm 运行，并共用对话框对两者给出的那条警告。

Host 测试覆盖随附默认值、配置的列表、从目录读出的包名，以及让 git 地址、压缩包、没有可读 manifest 的目录和被拒绝的 spec 保持未安装的读法。客户端测试覆盖列表条目、按条目 spec 一键安装、已安装的读法、没有标题的条目，以及让列表不显示的读取被拒、对话框关闭和 store 已释放三种情形。
